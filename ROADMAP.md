## Where the optional pieces plug in (and why they're optional)

**LLM question tie-break (Step 4, done):** used only as an optional tie-breaker when picking the next question — "if there are 5 equally good next questions, ask an AI which one sounds most natural here." If `LLM_API_KEY` is never set, or the AI is slow/wrong/broken, the system silently uses its own deterministic pick instead.

**LLM eligibility-rule drafting (`extract_rules.py`, Step 9a):** runs once, offline, not during a live call. Reads each scheme's real eligibility text and proposes structured rules — but only from a fixed, known vocabulary (the same 33 attributes `question_bank.yaml` already uses), and every rule must carry an exact quote from the source text or it's thrown away before ever touching the database. Rules land with `verified=0`; a human still checks a sample before anything is trusted, exactly like the original fully-manual plan, just with a faster first draft.

**LLM live wording (`present.py`, Step 9b):** runs per call, but only *after* `narrow.py` (deterministic SQL) has already decided which schemes qualify — this module can never add or remove a scheme, only choose how to say the name and pick which one real sentence of benefit text to speak. Every sentence it picks is checked to be an exact substring of the scheme's own database row before it's ever spoken; a paraphrase, a changed number, even a reformatted space fails that check and falls back to a safe default. If `LLM_API_KEY` is unset or the call fails/times out, this happens on every single presentation with zero exceptions — the fallback is not a rare path, it's the tested, always-available baseline.

**Sarvam (Step 10, done, key not configured):** the only thing that turns text into speech and speech into text. `voice.py`'s `tts()`/`stt()` are built, tested (`tests/test_voice.py`), and cache every clip to disk by content hash — but with no `SARVAM_API_KEY` in `.env` right now, the system stays text-only, which is exactly what `sim.py` (Step 8) already demos. Add the key and every prompt starts speaking with no code changes; run `scripts/warm_cache.py` once afterward to pre-generate all of `question_bank.yaml`'s static prompts so a live demo makes almost no Sarvam calls.

**Twilio (Step 11, done, account not configured):** the only thing that connects this to a real telephone number. `twilio_adapter.py` is built and tested (`tests/test_twilio_adapter.py`) as a second FastAPI router mounted onto `api.py` — same engine, same session-per-call model, translating Twilio's webhook payloads into the identical events `sim.py` sends and `step()`'s actions into TwiML. It verifies `X-Twilio-Signature` whenever `TWILIO_AUTH_TOKEN` is set. With no Twilio account configured, drive the same webhook contract directly (curl or the test suite) instead of a real phone number; add Twilio credentials and point a number's voice webhook at `/twilio/voice` (via `ngrok` for local testing, per SETUP_KEYS.md) to receive real calls.

**In short:** Steps 0-8 and 10-11 are done — a complete, correct, fully offline call simulation (`python -m haqdaar.sim --trace`, zero API keys) that becomes a real, speaking phone call the moment Sarvam and Twilio keys are added, with no logic changes required either time. Step 9 is now partly automated (LLM-assisted eligibility rules + live wording, both mechanically guarded so a bad LLM response can never reach a caller as invented content) instead of 100% hand-written — the human-review step still exists, it's just reviewing a first draft instead of writing from scratch.
