Every request/response pair below is a real HTTP call captured from a running uvicorn server hitting the actual api.py → engine.step() path — nothing hand-written. This is what a Twilio adapter (or the CLI simulator) actually sends and receives.

Pick a scenario on the left. Each turn shows the exact HTTP request sent and the exact JSON response that came back — say actions (what the IVR speaks), gather (what it's waiting for), and the state snapshot (phase, candidate count, answers so far).
Two calls started at the same instant, on two different threads, each answering the language question differently. If sessions ever crossed wires, one call would show the other's answer. api.py guards _sessions with a lock and keys every call by a fresh UUID — here's what came back for real.
A caller who already has a code (from a leaflet, or read out at the end of a previous call) can skip the questions entirely. 011 = scheme 01, section 1. 054 hits an unverified scheme — notice the deadline sentence is already gone. 999 doesn't exist.

To run this yourself in a terminal, with .env absent (no API keys at all):
$ python -m haqdaar.sim --script 1,2,1,1,1 --trace
--trace prints the candidate count after every turn — watching it drop is the whole point. --script replays a fixed key sequence; drop it for an interactive call you type into by hand. --dial 011 jumps straight to a section, same as the Dial tab above.
